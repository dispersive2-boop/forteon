# ForteOn · 30 идей: карта выполнения

Документ фиксирует статус каждого пункта: что уже есть в коде, что делаем,
в каком порядке. Обновляется по мере работы.

Легенда: **есть** — работает, проверить и при необходимости доработать;
**частично** — есть основа, нужна доработка; **нет** — делать с нуля.

---

## Главный сценарий

Открыть клиента → надиктовать итог → сразу получить рабочий план.
Суммы, документы и контакты — в той же карточке.

| 21 | История клиента одной лентой с фильтрами по типу | **есть** | `GET /clients/{id}/history` собирает события из журнала аудита по клиенту и по всему, что к нему относится: счёта, оплаты, зачёты, задачи, проекты, **договоры и документы** (последние два раньше писали в аудит, но в ленту не попадали — «одной лентой» история не была). Денежные события видны с суммой и «было → стало». В карточке — фильтр: всё, деньги, задачи, проекты, договоры, документы, карточка, заметки, с подписью «Показано N из M». Тесты: 4 |
| 22 | Напоминания: срок, риск, вопрос; одно обновляемое для повторяющихся | **есть** | `services/notifications.py::upsert_reminder`: повторное событие обновляет живое напоминание, а не плодит копии. Прочитанное не переиспользуется (это новое дело), отложенное — не затирается (иначе snooze отменялся бы сам). Тесты: 6 |
| 23 | Утренний дайджест менеджера с настройкой времени | **есть** | `services/digest.py`: `build_digest` считает сводку (сегодня / просрочено / оплаты на неделе / просроченные счета / ждут уточнения), ничего не записывая. `send_due_digests` крутится в существующем потоке watcher и рассылает, кому пора. Время менеджер задаёт сам в настройках (`users.digest_time`, «ЧЧ:ММ»; пусто — выключено) через `PATCH /auth/me/preferences` с проверкой формата. Строка сводки видна на «Сегодня», `POST /digest/send` позволяет проверить её сразу. Повтор в тот же день не плодит копий: заголовок содержит дату. Чужие счета в сводку не попадают. Тесты: 11. Живая проверка: `09:00` → `08:15`, `25:99` → 422 |
| 24 | Отложить напоминание, не меняя срок задачи | **есть** | `POST /notifications/{id}/snooze` переносит только `scheduled_at` уведомления, задача и её срок не трогаются. В колокольчике — «Через час» и «Завтра в 9:00». Проверено тестом п.22: отложенное напоминание не затирается повторным разбором |
| 25 | Предлагаемый текст следующего сообщения с источником | **есть** | `services/suggest.py`: `suggest_message` собирает текст по типу задачи (звонок / оплата / документ / встреча / письмо) и **обязательно называет основание** — `source_kind` + `source_quote` + `source_label`. Приоритет источника: цитата из заметки, по которой создана задача → открытое обещание клиента → последняя заметка. `GET /tasks/{id}/suggest` отдаёт `MessageSuggestion`; в карточке задачи блок «Что написать клиенту» показывает текст и строку «Основание: … — „цитата“», кнопка «Подставить в заметку» переносит текст в поле. Отправку по-прежнему делает менеджер. 7 тестов (`test_suggest_message.py`), живая проверка на 15 задачах: источники task 7 / commitment 1 / note 7, поля ответа совпадают с типом фронтенда |
| 26 | Своя схема списка клиентов (фильтры + колонки) | **есть** | `clients/page.tsx`: `CLIENT_COLUMNS` — 5 колонок (ближайшее дело, юрлицо и адрес, статус, обновлён, риск с причиной). Панель «Колонки: N из 5» включает/выключает их на ходу, подпись под именем собирается только из выбранных. Набор колонок хранится отдельно (`forteon.client-columns.{id}`), а схема (`forteon.client-views.{id}`) запоминает **и фильтры, и колонки**: нажатие на схему восстанавливает оба слоя одним действием. `normalizeColumns` отбрасывает незнакомые ключи, поэтому старые схемы не ломают список. Имя и переход в карточку остаются всегда. Живая проверка: все поля колонок приходят с сервера (юрлицо 100/100, адрес 78/100, ближайшее дело 51/100), фильтр по несуществующему статусу и поиск мусора дают 0, поиск по слову имени — ровно нужного клиента. `tsc --noEmit` чисто |
