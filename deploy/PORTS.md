# Порты ForteOn

## Итоговая раскладка

| Порт | Компонент | Привязка | Наружу |
|---|---|---|---|
| **8080** | ForteOn frontend (Next.js) | `127.0.0.1` | только через Caddy |
| **8081** | ForteOn backend (FastAPI) | `127.0.0.1` | только через Caddy (`/api/*`, `/health`) |
| 80 / 443 | Caddy (TLS, reverse proxy) | `::` | да — единственная точка входа |
| 3000 | **Ваш AI-агент** (Open WebUI, `rin-ai.pro`) | — | через Caddy |
| 8000 | Было занято тестовым запуском ForteOn | — | **освобождено**, не используется |
| 3100 | Временный dev-сервер ForteOn (только отладка) | — | не нужен в production |

## Почему 8080 и 8081

- **3000 занят** Open WebUI — это ваш AI-агент (`rin-ai.pro`), его трогать нельзя.
- **80/443 заняты** Caddy — единственная точка входа с TLS.
- **8000** ранее использовался тестовым прогоном; в production наружу не публикуется.
- **8080/8081** свободны, не пересекаются ни с агентом, ни с Postgres (5432), ни с sing-box (7891).

## Схема запросов

```
Браузер ──HTTPS:443──► Caddy ──┬──► 127.0.0.1:8080  Next.js   (forteon.pro/)
                               └──► 127.0.0.1:8081  FastAPI   (forteon.pro/api/*, /health)

Браузер ──HTTPS:443──► Caddy ─────► 127.0.0.1:3000  Open WebUI (rin-ai.pro/)
```

Оба сайта живут на одном Caddy, но на разных хостах (`Host`-роутинг) и разных внутренних портах. Пересечения нет.

## Проверка занятости портов

```powershell
Get-NetTCPConnection -State Listen |
  Where-Object {$_.LocalPort -in 8080,8081,3000,8000} |
  Select-Object LocalPort,OwningProcess
```

## Firewall

Публично нужны только 80/443 — правила `Rin-Caddy-HTTP-80`, `Rin-Caddy-HTTP-443`, `Rin-Caddy-HTTP3-443` уже созданы.
Порты 8080/8081 привязываются к `127.0.0.1`, поэтому правил firewall для них **не требуется**.
